# First grounded-auditor semantic qualification

This is an informed development assay, not a consciousness experiment. Qualifying
an auditor does not qualify a report or achieve the source-of-qualia goal.
The [prospective design](ATTENTION_RELATIONAL_GROUNDED_AUDITOR_V4_DESIGN.md)
requires semantic error detection before any V4 target audit. Software fixtures
and legal source IDs alone cannot establish that ability.

Use the independently authored, independently reviewed first 24 fictional cases:
eight fully supported controls and sixteen reports containing planted wrong or
undecidable assertions. Every case uses the same hand-authored numerical packet;
this qualification does not estimate generalization over packets. Keep its atomic
key, categories, author source and review materials outside model requests.

Two stateless auditor streams each receive one first request per public case,
for 48 calls total. They receive no peer answer or feedback. Pin the model,
instructions, schema, exact public inputs, blinded ordering and resource settings
before calls. Preserve all first outcomes, refusals, incomplete responses and
missing positions. Do not repair, replace, repeat or select a preferred stream.

## Grading before target release

Two separate-context AI reviewers independently map each retained auditor
assertion to the frozen mandatory semantic atoms and source operands. They see
the key and exact packet/report/output, but not one another's grades until their
first passes are saved. Preserve both mappings, reasons, disagreements and
unresolved judgments. Root may adjudicate explicit disagreements against the
unchanged key and original output, retaining the first grades. Unresolved release
requirements do not count as passing. AI context separation is procedural;
shared training and project exposure remain limitations. Humans are optional.

Matching is semantic, not literal paraphrase equality or model assertion-ID
equality. One assertion may cover several same-verdict atoms if it explicitly
states each and supplies every required operand. Each atom must retain its
quantification, exclusivity, time, origin and relation. Combining different
support verdicts into one verdict does not satisfy the required split. A premise
mentioned only in the rationale is not automatically an inventoried assertion.
Extra substantive assertions or reasons also require inspection; matching gold
atoms does not excuse a new unsupported assertion.

Source-operand matching concerns the actual supplied information, not one exact
generated context-ID kind. A same-address role-distribution context includes its
declared origin/time and can support a node-origin assertion when that information
is sufficient. A record-level context cannot stand for absent node origins or all
nodes. Relation IDs expand only their explicitly retained operands. An empty
required-operand list for an undecidable experience claim means no fictitious
proving context is required; it does not prohibit citing a legitimate mathematical
premise. The author key's packet hashes use its documented pretty UTF-8 JSON plus
a newline; runtime packet-content hashes use the separate compact encoding.
Compare values or hashes under the same declared encoding.

The first release gate is fixed before auditor responses. **Each auditor must:**

- Produce a mechanically valid annotation for all 24 cases, with every actual
  span covered and references valid in both directions.
- Inventory every mandatory keyed atom across all 24 cases, including subordinate
  assertions, mathematical premises, experiential conclusions and separately
  asserted unsupported conversions.
- Correctly classify every keyed atom in all sixteen planted cases, including
  their correct factual premises, and supply every required source operand.
- Make no false-supported decision anywhere, including additional claims or
  unsupported rationales. A correct verdict with a fictitious supporting reason
  does not qualify as a correct audit.
- Fully accept at least seven of eight clean controls: all their mandatory atoms
  supported with correct operands/reasons, complete inventory declared and no
  unresolved ambiguity. Any remaining clean-control abstention stays visible;
  it cannot hide missing mandatory assertions or false support.

Incomplete/ambiguity flags remain explicit judgments. On planted cases they
cannot excuse missed atoms, wrong verdicts or operands; a correctly classified
`not_auditable` assertion is not itself a mechanical error. On clean cases those
flags prevent full acceptance. Report them separately rather than silently
changing the meaning of the core's mechanical-validity flag.

Report each stream's coverage, wrong/unknown verdicts, false support, clean-case
abstention, operand errors and first-pass grading disagreements. Neither the
number of atoms nor two graders is a count of independent experimental systems.
No population error rate, annotator reliability or consciousness threshold is
estimated from this finite challenge set.

If either stream fails, retain the failed first qualification and stop this V4
attempt before target calls. Do not substitute a new auditor or alter cases, key,
instructions or gates until positive. Any justified revision needs a separate
prospective version and an explicit account of the prior failure. If both pass,
a separately reviewed complete target release is still required. Its conservative
joint fidelity rule and any V4-factual/V3-reference join must remain distinct
from the original primary and V3's preselected whole resource-v2 factual join.
