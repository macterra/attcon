# Grounded source-aware auditor v4: prospective design

2026-10-19. Design only; no target calls or runtime release. The goal remains
credible evidence for the theory that the attention-control model is the source
of qualia. This repairs a failed measurement method; it does not define
qualia, require task necessity, or conflate Reporter with Controller.

The design follows the preserved original audit failure and the resource-v2
fixed-prefix contract failure. Its author inspected original contract diagnostics
and, while reading the published original-results document, its COD/CA aggregate
table. No live resource-v2 semantic responses were inspected. This is informed
development on existing reports, not output-unexposed confirmation. Preserve the
old instruments, raw judgments, interrupted versions and failed gates unchanged.

## Finite question and corpus

Can a source-aware instrument reliably inventory substantive assertions and judge
their support, when code supplies literal evidence locations and legal source
addresses? Distinguish schema success from semantic error detection.

Use the same 552 narrator opportunities on 12 archived cases: 537 available texts
and 15 unavailable positions. Preserve every source/view/intervention, unchanged
control, restoration, null and incomplete narrator. No new narrator, world, source
fit, preferred-case selection or altered consciousness-reference definition.
Literal templates remain separate fixed controls, with their exact-source
construction checks retained.

The finite execution is: freeze the interface and independent challenge key;
qualify on 24 fictional reports; if qualified, collect one full supplementary
measurement; publish all outcomes. Failure ends this v4 attempt before target
collection. Do not repeat challenges, swap auditors or tune gates until positive.

## Deterministic report and source addresses

The new request contains the exact original report, a lossless span table, the
same neutral numerical packet and a source-context table. Freeze one mechanical
span-partition rule before qualification: split after a line break or a sentence-
terminal punctuation mark followed by whitespace; retain separators in adjacent
spans so ordered intervals concatenate to the exact text. Abbreviations can yield
short units; these are addressing units, not presumed atomic propositions.
Assign opaque span IDs in order. Code, not the model, retains exact strings,
Unicode offsets and report-text hash. No text normalization or paraphrase enters
the evidence table.

Assign legal context IDs from the actual packet. Specific IDs resolve to a panel,
current/candidate view, concrete command where applicable, node, role and declared
time/origin. Record-level IDs resolve to actual metadata without invented node,
command or role values. Relation entries preserve every operand, including both
roles and each distinct node/panel/time. Optional source-fact IDs may name only
transparent calculations already licensed by the packet: exact peaks/ties,
probabilities, entropy, expectations, peak relations and declared origins/times.
Keep the full numerical packet available; the fact table is not exhaustive truth.

These IDs prevent illegal nullable combinations. They do not determine whether a
claim is supported. They supply no architecture/source identity, intervention
label, evaluator truth, peer answer, reference rubric or desired language. Copied
records, estimates, conditional forecasts and executed snapshots remain distinct;
no context ID promotes them to current experience or world truth.

## Raw annotation and derived evidence

Use a new raw schema and instruction version. The model selects IDs; it never
copies a quote or calculates an offset. For every report span it returns exactly
one coverage entry: its assertion IDs, or an explicit nonassertive classification
with a reason. Every substantive assertion has an ID, a paraphrased assertion
statement, report-span IDs, all applicable context/fact IDs, support verdict and
reason. The paraphrase is an auditor judgment, never original quoted evidence.

Split compound clauses whenever support differs. Multiple assertions may cite
the same span; one assertion may cite several spans. Cover temporal/origin
presuppositions, hedges, negations, comparisons and claims about all nodes or
commands explicitly. A broad assertion requires all its operands; a missing
address cannot be silently expanded to all addresses. Unsupported experiential
claims need no fictitious supplied context.

Retain the original meanings: supported follows from supplied facts and semantics;
contradicted conflicts with them; not_auditable is undecided by them. Felt truth,
actual presence, unsupported causes and probability-to-clarity conversions are
not supplied facts. Unknown never becomes contradicted, absent or a negative
consciousness finding. A claim outside the calculation table is still assessed
against the full packet; the table's omission is not evidence of falsity.

Code checks exact ID inventories, coverage references, legal contexts and operands,
then derives exact span strings/intervals without changing any judgment. Keep
three separate objects: raw first model response with its true request binding;
derived evidence with ID mappings and hashes; scientific assessment. Noncontiguous
evidence remains separate spans, never a fabricated contiguous quotation. A
mechanically complete coverage table cannot prove that the model found every
claim. Missing substantive assertions are a semantic failure tested below.

## Semantic qualification before target calls

A separate-context author creates 24 short fictional packet/report cases: eight
fully supported technical controls and sixteen cases containing planted errors.
Collectively the latter include wrong numeric/role/location facts, conditional-
as-executed claims, copied-prior-as-new-estimate claims, false origin/time claims,
unsupported experience, uncertainty-as-felt-clarity, contradictory compound clauses
and easily omitted subordinate assertions. Include correct uncertainty and neutral
model-organization descriptions as controls, without treating them as appearance.
Use ties, multiple panels and multi-operand relations as appropriate. No actual
target report or reference-rating example becomes a challenge exemplar.

The hidden key lists every mandatory atomic assertion, expected support verdict,
source operands and deliberate nonassertive spans. A separate-context reviewer
checks that each verdict is decided or undecided by the packet as stated. Resolve
key ambiguities before answers; preserve disagreements. Freeze the key, prompts,
settings and all 24 cases before fresh responses. No key, planted-case category,
expected verdict or peer answer goes to an auditor.

Two stateless source-aware auditor contexts each take one first pass over all
24 cases. Separately assess semantic assertion coverage, planted-error detection,
false-supported decisions, over-abstention on clean cases and source/time/operand
correctness. Reviewers must compare actual extracted assertions and reasons to
the hidden key, not merely accept IDs or JSON. Preserve first mappings, grading
disagreements and uncertainty; do not retrospectively delete disputed cases.

Proposed bounded release criteria, to be independently checked before freezing:
each auditor satisfies the full mechanical contract, covers every mandatory keyed
assertion, correctly classifies every planted assertion, supplies its required
operands, makes no false-supported decision and fully accepts at least seven of
eight clean controls. Compound-case omissions fail coverage even if every listed
claim is correct. Remaining clean-case abstentions stay visible. These are finite
instrument qualification rules, not theory-success thresholds, population error
estimates or proof of semantic completeness. If the first qualification fails,
retain it and do not collect v4 target audits. Any correction needs a new version.

## One supplementary measurement and honest join

If qualification passes, the same two auditor contexts independently assess every
available target report once: 2 x 537 calls, with all 2 x 552 opportunities retained.
Both see the same neutral source data and no peer output/reference judgments.
Use the existing pinned model, medium reasoning, low verbosity, 32,768-token cap,
600-second timeout, concurrency six overall, store false and zero retries. Freeze
exact instructions, schema, ID derivation, requests, lineages and roots before
calls; combine source/method review and stage release into one bounded review.
The fictional qualification also tests transport; do not add repetitive unscored
acceptance cycles after a successful identical interface qualification.

Report each auditor's full result separately. Prespecify a conservative joint
fidelity rule: valid available narrator, existing complete listed-fact gate, and
both audits mechanically valid, claiming complete coverage and judging all
substantive assertions supported without unresolved ambiguity. Different claim
segmentation is not automatically disagreement or agreement; preserve inventories
and span-level disagreements without choosing a preferred annotation. Agreement
is corroboration within a shared-model instrument, not independent validation.

Before v4 target outputs, declare one distinctly named supplementary v4-factual /
v3-reference join over the complete version. Bind the exact V3 reference version,
all report/text hashes and v4 factual rules. Preserve raw correspondence and each
fidelity-conjoined result separately; no favorable per-item mixing with original
or resource-v2 audits. The existing V3 join's preselected whole resource-v2 factual
substrate remains unchanged and unestablished wherever invalid or unavailable.
A v4 join cannot replace that earlier result or masquerade as its completed
primary. It uses actual new request/response lineage, not patched old bindings.

Publish qualification and complete target outcomes, disagreements, missingness,
source-specific facts, reference correspondence and causal/restoration controls.
Factual success alone does not achieve the goal. Positive source-linked
correspondence can motivate fresh powered confirmation and replication on fresh
systems/tasks; these repeated twelve development cases cannot supply them.
