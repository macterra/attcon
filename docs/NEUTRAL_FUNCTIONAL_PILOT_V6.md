## Typed source-blind process audit

Categorical auditor v1 and its retained 14/14 qualification remain unchanged.
New process auditor v2 retains its pinned model, medium reasoning, 16384 output
tokens, 240-second timeout, concurrency 6 and no retries. It receives numbered
prose only, without source state, owner, variant or the categorical auditor's output.

Use separate nested schema branches:

- Selection: `position=null`, selected position in `value`; current command is null.
- Unattended recovery trend: addressed position, current scope, command null.
- Explicit selection-forecast presence metadata: `position=null`, `value=present/absent`.
  Current scope has command null; command scope addresses an explicit command or,
  when quantified collectively, all commands with command null.

An unidentified selected position in a supplied model forecast remains a selection
claim with null value. An absent forecast in the **record** is a presence claim.
An unreported selection in the **prose** is neither. Positive selection claims about
an output node must still be extracted and conservatively rejected by the scorer.
Do not infer presence merely because an ordinary selection assertion implies it.
Preserve invented position/node values and unresolved addresses.

The schema forces selection addresses to null, rather than relying on instructions
to prevent duplicate position fields. Nested unions are supported in the
[OpenAI Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs).
This constrains structure, not semantic truth. The local validator checks the same
address/scope contract in raw parsed assertions.

## Frozen factual gates

Each neutral, remapped, conflicting-description, model-swap and restored group
requires checked accuracy >=98%, conservative precision >=95%, identified output
coverage >=90% and process coverage >=90%. The numeric minima are unchanged.
Primary accuracy/precision now also check explicit selection-forecast metadata.
These additional facts earn **no process coverage**, whose expected set remains
18 facts per full report and 10 per missing-relation report.

Presence is checked against whether the addressed record contains selection fields,
not whether its dominant selection is known. An output readout may correctly have
no selection forecast while its categorical contents remain available. A missing
command table supports absence of selection forecasts for known nodes and known
commands k0–k3, but no positive command prediction. Collective presence/absence
requires agreement across all provided command trials; unresolved scope earns no
coverage or conservative correctness. Unknown command IDs remain unresolved.

The missing-relation control must produce no command prediction or positive command-
access feature. A truthful explicit absence of a command selection forecast is
metadata, not a command prediction, and is excluded from that prediction count.
It remains included in factual precision. No other unsupported assertions are excused.
