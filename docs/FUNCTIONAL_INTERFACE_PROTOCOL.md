# Three-way learned visual and neutral interface export v1

2026-10-04. Engineering-development export, frozen before materializing its new
scene data and records. It connects the completed [three-way forecast study](FUNCTIONAL_CONTROLS_RESULTS.md)
to the factual reporting interface. It does not train models, generate prose,
qualify a language auditor or assess consciousness-report character. The overall
parent engineering failure remains unchanged. Reporter and Controller are separate.

## Inputs and architecture

Use the fixed final attention models 2011/2021/2031, paired with existing visual
encoders 1301/1311/1321. Dependency hashes cover all checkpoints and original
forecast traces/records. No new training, checkpoint selection or replacement is
permitted. Each pair receives 512 fresh rendered scenes, seed `750000000 + visual_seed`.
Copy buffer-0 patches to buffer 1 so object identity does not disclose wiring.
Record visual class predictions and physical labels separately for verification;
physical labels and condition/owner IDs never enter the reporting payload.
The inherited visual joint-accuracy engineering minimum is 99%; retain any failure.

Content distributions use the existing explicit bridge:
`visual*q + uniform*(1-q)`. This is an engineered uncertainty interface, not learned
phenomenology. Current q and all four prospective q arrays come from the learned
attention model. Physical recovery and true wiring do not replace its predictions.
The decision-output readout copies buffer 0; this identifies the fixture's task
boundary, not a phenomenal boundary or a new autonomous Controller benchmark.

## Exported causal views

All 512 episodes retain full modeled allocation/access/effects and recurrent state,
prospective recovery and histories in each exported context:

- Static conditions buffer 0, buffer 1 or neither controlled.
- Static model-only effect-channel swap, with allocation/access/hidden state fixed.
  Restoration must exactly recover the baseline prospective forecasts and payload.
- All nine old→new world pairs, no-feedback and feedback, at 16 post-switch steps.
  Replay the original model updates and verify effect/prospective forecasts against
  every original archived window (1/2/4/8/16), without changing the parent scores.

No-feedback states receive only their initial physical history. Subsequent predicted
events are explicitly `anticipated_history`, never `observed_history`. Feedback
states include actual post-switch observations. Both contexts have modeled step 28,
with the same post-switch command sequence. For each old condition, the no-feedback
state and payload must be identical across all unobserved new-world choices.
True new wiring remains evaluator-only information.

## Factual payload and presentation controls

Use the existing complete-interface factual domains: current object categories,
buffer selection distributions/selected positions, recovery at unattended delays
0/1/2 and its declared trend, and per-command object and buffer-selection forecasts.
Round probabilities to five decimal places; identified category/position threshold
is 0.6, unattended-trend thresholds are ±0.02. Retain null categories explicitly.
The output readout has no invented separate attention or recovery field.

Static record rows 0–5 span all six node-order permutations, equally across every
condition/model. Six variants are neutral, reversible node+command remapping,
untrusted conflicting note, missing relation, model-only swap and restoration.
Missing relation removes both histories and all command forecasts while retaining
current facts. Remapping changes presentation identifiers only; it does not test a
novel physical command mapping or held-out language generalization.

Revision records use the same six rows/orders for every route/context, with no
condition label in the payload. Additionally export both contexts for the eight
previously identified seed-2021 route 1→neither failures. This targeted diagnostic
sample is post-hoc and must not be treated as random or used to estimate prevalence.
There are **664 records**: 324 static presentation variants, 324 revision views,
and 16 targeted diagnostic views. These are input fixtures, not language reports.

Evaluator envelopes retain opaque record IDs, seeds, row, condition, variant and
order for linkage. Only `payload` may be passed to a future reporter; the envelope
must be excluded. No prompt/model/API configuration is frozen by this export.

## Invariants, archival and next gate

Verify source/dependency hashes, all original forecast equalities, exact restoration,
unchanged current facts under model-only swap, readout-to-buffer-0 equality,
reversible identifier transforms, and separation of anticipated versus observed
events. Preserve original parent failures. Export status must not call those
checks a theory-facing success. Archive new tensors, records and checksum summary;
replay all values without training or API calls. Refuse to overwrite an export
attempt. Publish protocol/source/preparation before export and results afterward.
