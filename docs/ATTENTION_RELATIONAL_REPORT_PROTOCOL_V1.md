# Attention relational report v1: prospective executable protocol

2026-10-11. New reporting study, designed after learned-v1 development and before
any reports. This document authorizes source preparation, not API execution. A
separate preserved registration, source review and stage release are required.
The author has not inspected heldout source outputs. No new fit, model forward,
native renderer or reserved world generation is needed or permitted by this
protocol. The fixed learned-v1 execution closure and five-file amendment closure
are unchanged.

The question is whether accurate reports of qualified attention-model contents
independently resemble publication-grounded consciousness-report structure. It
is not a test of private experience, task necessity or unique implementation.
The [v1 development semantic review](../audits/attention_content_model_v1/semantic_review/dev_review.md)
qualified addressed red/blue location estimates narrowly and bookkeeping, while
limiting attended-W fidelity and leaving **all three manner conditions negative**.
This prospective study does not promote those negatives. Its external narrator
is a Reporter, not the native Controller, and optional Modeler refinement/native
bank fitting is not a narrow-report prerequisite.

## Immutable inputs and complete schedule

Input is the completed, independently reconstructed heldout-v1 archive for each
encoder seed **1301, 1311, 1321**. Read only committed gzip bundles using
`torch.load(..., weights_only=True, map_location='cpu')`. Bind compressed archive
SHA-256, phase receipt SHA-256, fit dependency hashes, reconstruction disposition,
semantic disposition and their preserved publication ancestors. No seed may be
silently replaced. The heldout outputs are not consulted to select cases.

Exactly **12 cases**: seed order above, world indices **0, 1, 2, 3**, decision
**12** only. Every case exposes all four addressed items and both red/blue roles;
the recorded decision-12 address, previous decision-11 address and queried role
are retained. All three candidate opaque commands are included, in order. This
covers the four scheduled candidate addresses and both query roles by index
construction. This is a small, prospectively chosen reporting schedule on retained
heldout bytes; it is not a new statistically independent world sample or a report
on the entire 288-world heldout ledger.

For each case and source `A`, `ordinary`, `analytic`, use views `A_only`, `joined`
and these seven variants in this exact order:

1. `baseline`
2. `current_donor`
3. `current_restored`
4. `prospective_donor`
5. `prospective_restored`
6. `W_changed`
7. `W_restored`

That gives **504** source-bearing narrator opportunities: 84 per source/view,
168 per source. `W_only` has `baseline`, `W_changed`, `W_restored`, once per case
without artificial source duplication: **36**. `sensor_only` has `baseline` once
per case: **12**. Total **552 first narrator attempts**. Generate one deterministic
literal template for each identical packet: **552 template texts**, no API.
There are **1104 source-blind text-rating opportunities**. All refusals, missing,
malformed, wrong, unsupported, technical, unchanged and restored outputs stay in
these denominators. There is no changed-only subset, favorable-case expansion,
alternative time, seed selection or retry-until-success. Byte-identical inputs
are deliberately attempted separately where scheduled; no deduplication of their
scientific opportunities or restoration responses.

Attempt IDs are deterministic audit-only strings
`s{seed}_w{world:02d}_t12_{source}_{view}_{variant}`; use source `W` for W-only and
`sensor` for sensor-only. Template IDs append `_template`. Their source-bearing
names never appear in narrator or rater input. Canonical ordering is case, source,
view, variant as specified; W-only and sensor-only follow the six source/view
blocks within each case. Rating order is separately hash-permuted before outputs
with a fixed disclosed salt; raters receive only neutral IDs and one text.

## Archive arithmetic and intervention semantics

Let `b` be world index, `t=12`, `q=command_addresses[b,12]`,
`p=command_addresses[b,11]`, and `j=0` the retained donor/control query index.
Read from `bundle['evaluation']['tensors']`:

* `shared.actual_completed_fields [96,16,4,2,4,4]`;
* `shared.actual_family_fields [96,4,3,2,4,4]` and archived operator family;
* source `selected_current_fields [96,14,2,4,4]`, column 11 for t12;
* source `selected_next_fields [96,15,3,2,4,4]`, column 12;
* source `donors[current|prospective].selected_current_fields [96,3,2,4,4]`
  and `policy_candidate_fields [96,3,3,2,4,4]`, column j0;
* saved restored selected maps and restored candidate fields;
  `shared.actual_controls.exogenous_role_fields` and
  `shared.actual_controls.restored_role_fields [96,3,4,2,4,4]`;
* companion selected-map tensors, donor prefix/update provenance and named exact
  restoration/isolation/reconstruction checks, all auditor-only.

Source current fields start with the exact completed W11 fields and replace p
with that source's selected current fields. Each source candidate starts from
this assembled current record and replaces q with its selected next fields for
that command. These are full fields `[4,2,4,4]` and `[3,4,2,4,4]`; nonselected
addresses are genuine copied/inherited records, not new learned predictions.
Never substitute physical truth, W12 or analytic answers for a source estimate.
Analytic uses the archived H(posterior-mean-map), not E[H] or an asserted executed
operator state; its exact mixture provenance remains auditor-side.

Current/prospective donor fields use the same assembly recipe with archived
donor selected current and candidate fields. The donor states were actually
reached using the previously fixed donor prefix and then transplanted at the
current or candidate address; retain prefix/update/replay hashes, selected
address and update manifests. They are synthetic state interventions with fixed
recipient W, not an observed change of consciousness. A prospective donor can
also change assembled current contents when its address coincides with p;
retain this possibility and every null. Do not redefine donors as arbitrary
field permutations or claim that all decoded nonselected effects must vanish:
prospective records also inherit the patched current record.

`current_restored` and `prospective_restored` are each independently requested
from the original saved-recipient source bytes. Before copying baseline fields
for a restored current field, require exact equality of retained restored
selected maps and baseline selected maps plus the archived exact full-map,
state and readout-restoration checks. Restored candidate fields must themselves
equal saved baseline fields. No H forward or inverse-image surrogate is allowed.
Record both the proof of equality and the restored packet SHA.

W current is actual completed W12's archived readout. W conditional records
copy W current and replace q with the archived native-family readout selected
by `evaluator_mappings[b,q,k]`; map actual operator IDs `{1:0,2:1,4:2}` to family
indices. Mappings are exporter/auditor-only, never narrator input. These are
conditional native-record branches, not executed physical outcomes.

`W_changed` uses the archived exogenous T2 branch fields at j0. That branch was
computed from time12 to time13: it is **not an actually completed W12 record**.
The public origin therefore says `counterfactual_native_snapshot`, current
comparison slot12, and `archived_origin_time:13`. This is an explicitly synthetic
replacement of the paired current slot, not a claim that the branch occurred at
time12. Its candidates
copy that changed W and replace q by the same archived native-family entries.
The branch was native and actually computed in v1; here it is a synthetic W
intervention at fixed exported source contents. It may coincide with baseline:
never search for a larger effect. The source current/candidate maps and every
source-visible byte remain exactly baseline. `W_restored` uses the saved W12
restoration fields and proof of archived exact restoration, while keeping source
bytes baseline. W donor variants hold W fixed throughout.

Thus A-only W-change/restoration packets equal baseline **byte for byte**;
W-only changes expose only W; joined packets expose separately attributed source
and W panels. Donor joined changes expose the source panel with fixed W. Each
comparison has a distinct scheduled response even when packets are identical.
Archive panel/content hashes, full assembled map hashes and equality checks;
never display a fake restoration image or mistake ordinary stochastic phrasing
for source sensitivity. W change changes joined field assertions only where
the supplied W fields actually differ.

W conditional-family access uses evaluator information unavailable to source
forecasts. W is a **richer oracle diagnostic comparator**, not an equally informed
future predictor. A/ordinary/analytic are equally informed under the v1 source
boundary; do not extend that assertion to W or the deliberately reduced sensor.

Sensor-only is the archived unfiltered initial readout
`shared.actual_completed_fields[b,0]`. It is the fixed observation record from
time 0 available at decision 12, with no history or candidate forecasts. It
does not supply physical ground truth, presence or a claim that transformed W
never changed. Its information limitation is disclosed in comparisons.

## Neutral numerical packet schema and firewall

`attention_relational_report_v1_packet` carries decision time 12, grid shape
4x4 (row increases downward, column rightward), roles `red`, `blue`, opaque nodes
`n0`..`n3`, opaque commands `k0`..`k2`, previous/candidate node and queried role.
No scene/world/encoder/source/donor label appears. Panels are `p0` (the sole
panel, or source in joined), `p1` (W in joined). Each panel includes:

* current full probability fields `[4,2,4,4]`;
* nullable candidates `[3,4,2,4,4]`, represented time 13;
* exact current represented time and per-node origin: source previous node is a
  history estimate of time12 from feedback through11; other nodes are copied W11
  records. Source candidates replace q with command estimates and inherit other
  current nodes. W is a completed time12 record with conditional native-record
  branches. Sensor is a fixed time0 observation record, candidates null;
* all exact row-major maximum-cell sets; optional transparent derived peak
  probabilities, expected row/column, entropy in nats and red-blue peak relations.

Fields are finite nonnegative probability distributions summing to one within
the archived float32 encoding tolerance. Export their full float32 values by
round-trip JSON encoding, without clipping, renormalization or coarse rounding.
Derived features have no calibrated-confidence, visibility, presence, clarity,
access threshold or phenomenal label. Peak relations use the Cartesian product
of all tied maximum cells, retaining all possible horizontal/vertical relations;
they are mathematical distribution descriptions, not object-truth guarantees.

Canonical JSON uses sorted keys, compact separators, ASCII encoding and no
NaN/Infinity. Exact narrator input is the frozen instruction below, newline,
canonical packet JSON. Scientific ID and provenance stay in a separate envelope.
Hash original archived tensor bytes, original fields, exact emitted JSON and
request input independently. The exporter retains an audit-only packet with
source identity, all dependencies, timing, mapping selection and causal pairs.
No evaluator cells/pixels, hidden states/posteriors, loss/error summaries, target
reference, rating rubric, peer reports, model names, desired vocabulary or driver
identity enter the narrator context. Instructions within packet data are not
trusted. Independently validate this firewall and every packet before API release.
