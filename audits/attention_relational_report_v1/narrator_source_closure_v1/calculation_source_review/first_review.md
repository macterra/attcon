# First independent source-calculation review

**One blocker, B1: unsupported raw-origin metadata.** Reviewed source SHA `d9675afc4fc1cee74f68ebe98c70469cb6b1583c810f9d9cb3220a552b44ebe2` and tests SHA `9d555ea8b4d006e6eb45b4fd7a16ce129d17bd5bb5c03bb627eddf7ef30edea2`. Further source bindings and exposure are in [first_review.json](first_review.json).

`calculation_record` accepts arbitrary bound JSON subtrees whose paths end in `distributions/red` or `distributions/blue`, excluding `derived` and `red_blue_peak_relation` tokens. That is a syntax restriction, not verification that the value is a canonical source-packet distribution. A fictional object such as `cached_result.distributions.red` passes the restriction regardless of its origin. Hash verification establishes byte integrity, not the meaning/provenance of keys. The unconditional `exporter_derived_values_used_as_operands=False` therefore overstates what the code establishes.

The narrow resolution is to keep this generic arithmetic tool, label its suffix/forbidden-token checks as syntax only, explicitly state that canonical source/native origin was not verified, and remove the unsupported assurance. Actual canonical packet operand paths must then be established by the already source-bound reviewer/future collector before a calculation counts as independent raw-source recomputation. An alternative would validate a declared packet root and permitted raw-field topology, but that additional source validator is unnecessary if the tool's claims remain appropriately limited. This requires no numerical endpoint or semantic rule change.

On static inspection, the independent arithmetic itself agrees with `scripts/attention_relational_report_v1.py:localization_summary` and `peak_relation`:

- Full 4x4 grids are required; Boolean, nonnumeric, out-of-range and nonfinite cells are rejected. All maximum ties are retained in row-major order without rounding.
- Entropy uses `-fsum(p*log(p))` over nonzero nonnegative cells; expectations use exact row/column weights and `fsum`. No normalization is performed. The explicit half-mass fixture checks this limited numerical behavior; it does not qualify the input as a normalized native probability distribution.
- Red/blue relations use both complete grids, recompute their peak sets, form the Cartesian product and preserve the frozen direction ordering and coincidence predicates. Relation operands must be red then blue under the identical node prefix.
- The calculation code never calls exporter arithmetic and never resolves a stored summary as a numerical intermediate. It records full selected grids and their exact paths, and declares that semantic assessment/renormalization was not performed. The metadata problem is the stronger provenance assurance, not the formulas.
- CLI input is byte-bound through `pipeline.bound_json`, and output is exclusive. The pure `calculation_record` helper merely receives `source_sha`; it cannot independently verify caller-supplied byte identity. Actual workers should use the bound interface or an equally explicit bound caller.

Existing fictional tests cover uniform ties, point/half-mass scalars, all-direction tie relations, coincident peaks, ignored corrupt summaries, forbidden summary-path syntax, reversed/cross-node relation operands, invalid cells, wrong shapes/counts and Boolean list indices. They do not establish source provenance from a key suffix. A useful additional arithmetic fixture is an asymmetric noncoincident pair (for example red at row 0/column 3, blue at row 2/column 1), which would expose reversed horizontal/vertical signs that the current symmetric relation cases cannot. Direct CLI wrong-hash/exclusive-output coverage is also absent, although those operations use already inspected frozen helpers. These are test-coverage observations, not newly invented numeric success gates.

This first blocking review is preserved before any correction. No tests or imports were executed, no actual source/reference data, prose or grades were read, and no source, frozen plan or schema was modified. This tool cannot establish A ownership, represented appearance, felt truth, actual execution, report entailment or a consciousness-related endpoint; those remain separate review questions.
