# Independent fictional challenge author notes

This is the first authored version of 24 factual-auditor challenges: eight fully
supported controls and sixteen reports with planted errors or undecidable claims.
The author has not executed the builder, materialized cases or key, constructed
requests, made API calls, or read the new v4 auditor core. The builder imports
only the Python standard library. It reads no experimental archives or reports.
The source packet calculations were independently transcribed from the old
neutral exporter, not obtained by calling it on real sources.

The author is a separate AI subagent in the same project thread and model family
as the parent. Its authoring context is separate from the new auditor-core
author's context, but this is not independent empirical or human validation.

The author has prior access to original-result aggregate patterns and original
scientific labels while reviewing the original results document, and reviewed
the earlier fictional v3 quote-acceptance source/design. That exposure is not
erased by using a separate author context. No actual target report was read for
this authoring, and no live resource-v2 semantic response was inspected. This is
informed instrument development, not output-unexposed confirmation.

All 24 reports use the same fixed, full-format fictional two-panel public packet.
Each panel has four current nodes, three candidate commands, four candidate nodes
per command, and both red and blue 4x4 probability maps. Masses are hand-authored
dyadic float32 numbers. Statistics and Cartesian-product peak relations are
computed transparently. Candidate nodes other than n1 inherit their corresponding
current maps; nested origins preserve the time of the inherited current record.
Declared origin kinds follow the existing public semantics, without actual
architecture, source, intervention or experimental case identities. Reusing one
packet bounds factual complexity and makes all reports independently decidable;
it does not test generalization to unseen packet structures or independent cases.

The public case whitelist is exactly case_id, packet and report_text. Clean/planted
status, category names, atomic verdicts, reasons, source descriptors and evidence
locations exist only in the separate hidden key. Neither this script, its source
snapshots, the key, these notes nor the materialization manifest belongs in an
auditor request. Auditors must receive no peer answers or qualification labels.
The independent core author must not inspect the hidden key before completing
the core. The author of these challenges has not inspected that core.

Every authored sentence has a finite list of mandatory semantic atoms. Compound
and relative clauses include separate atoms where facts or verdicts differ.
Exact Unicode codepoint intervals locate literal evidence fragments; they do not
predict opaque span IDs or require one auditor paraphrase/segmentation. Only the
literal Notes heading is deliberately nonassertive. If an auditor groups several
atoms, grading must still check every atom, verdict, reason and operand. A valid
JSON coverage table does not establish semantic completeness.

Important distinctions in the key are intentional. A candidate declared to be
conditional contradicts a claim that the packet calls it executed; it does not
decide whether that command happened in the world. A positive cell probability
or entropy supports its mathematical premise and leaves the proposed conversion
to felt clarity undecided. Subjective claims have no fictitious proving context.
A singleton claim about a tied peak is false even when the named cell is a peak.
Nested inherited origins are not interchangeable with their outer candidate
times. Cross-panel comparisons concern local coordinate indices only, not a
shared physical location.

These are factual-audit qualification materials, without consciousness-reference
labels, positive reference exemplars or scientific target claims. The unsupported
experiential and clarity sentences are planted audit errors; they are not a
definition or reference example of an experience category. Qualification cannot
establish an appearance counterpart or theory success.

The fixed order interleaves two planted cases with each control; no outcome
selects an item, order, packet, phrase or key. Root must materialize once, preserve
all first files and independently review each gold verdict before any of the
48 planned first-pass qualification calls. The builder reserves an exclusive
output directory before construction and keeps partial failures. A new directory
is not authorization to repeat a failed qualification until it passes. The
