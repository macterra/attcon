# Relational reporting pipeline source preparation

2026-10-11. Source-only, before reporter/export/archive/API execution by this author.
Implements the [frozen protocol](../../../docs/ATTENTION_RELATIONAL_REPORT_PROTOCOL_V1.md)
without editing its committed files. This source author has inherited project
context; fresh stateless source-neutral narrator/auditor/rater requests remain
separate, with no claim of human or independent-family validation.

[Pipeline source](../../../scripts/attention_relational_reporting_pipeline_v1.py)
provides complete552-request export validation, exclusive request preparation,
exact stage-bound first-completion collection, source-aware prose auditor preparation,1104 blind
rater requests, deterministic machine/prose/reference validation and complete
summaries. It has no API client/model/renderer/optimizer/world generation.
Import is inert; CLI requires explicit bound JSON input SHA values and writes an
exclusive output. Root's API runner owns reviewed output-root binding, exact
committed manifests, batch claim before credential/client creation, per-request
claim before that request API call, all raw first responses and CLI failure logs.

Collection requires a reviewed stage manifest, exact request-file SHA/inventory,
reviewed output root, and hash-bound stage lineage JSON. Its runtime manifest
adds lineage_path and binds that file plus every underlying artifact hash. Each
first outcome request_sha256 is checked using the API runner's exact indented
JSON/newline encoding, not the packet's compact encoding.

Collection follows the bound first_completion response_path/SHA; it unwraps
secondary first_outcome or retained_first_outcome_envelope after double storage
failure. It never assumes id.json is the response. Interrupted collection retains
available partial files and marks conflicting paths ambiguous instead of choosing
a convenient success. Every raw response, refusal, incomplete status, malformed
JSON, duplicate key, nonfinite constant, missing record and storage failure stays
available; incomplete/refused/invalid responses never earn a positive endpoint.
Absent or malformed actor prose cannot earn even a possible-upper match from an
otherwise valid empty-text rater annotation; raw reported labels remain diagnostic.
Summary reconstruction binds report->export, audit->first-report/neutral-packet,
and rate->first-report/template/reference request inventories and content hashes.
Same-ID responses from a different batch or prompt cannot pass. Raw dependency
file SHA/path records remain alongside canonical content SHA records.

Instructions/reference are read programmatically from frozen files with exact
hashes. PROSE_AUDIT_RESPONSE_SCHEMA and RATER_RESPONSE_SCHEMA use fixed required
object fields/additionalProperties:false, primitive types/enums and arrays, with
no uniqueItems/allOf/if keywords. Narrator format comes from the separately owned
exporter REPORT_RESPONSE_SCHEMA. Audit input contains only neutral packet+first
prose; rater input contains only reference+opaque ID+text. The pipeline retains
all1104 rating positions, including empty missing-text positions, without giving
raters condition/status clues. Auditor missing-text positions remain unestablished
and cannot generate substitute actor/auditor calls.

Exact quotes, Unicode offsets, allowed enums, compatible composite feature/time/
scope/referent evidence and source binding validity are checked. Quote-present
but offset-wrong ratings are distinguished from fabricated quotes, retained
without correction and barred from positive counts. Raw reported labels and
rater limitations remain in the summary. These checks validate recorded evidence
structure, not a semantic rater's infallibility or all free-prose extraction.

The summary preserves all seeds/sources/views/variants, full25440 required peak
opportunities per narrator/template arm, source fidelity independent of COD/CA,
explicit lower/explicit-or-ambiguous upper counts and rates, scoped features,
invalid/missing measurements and684 fixed causal pair records. It retains panel
assertions separately for source and W; matched machine claim changes are
separated from absent optional claims and stochastic wording. Input restoration
never requires literal text restoration. There is no goal-completion or positive
experience flag, no threshold revision, and no v1 manner promotion.

The handcrafted fixture source covers semantic-audit failure despite correct
machine claims, missing conditional coverage, invalid bindings, Unicode quote/
offset failures, future-to-current composite promotion, source-blind request
firewalls, secondary/inline storage retention, incomplete/malformed first outputs,
stochastic restoration wording and exclusive writes. One tiny mocked-inventory/lineage
summary fixture checks reference/fidelity conjunction; it does not validate the
production552-case schedule or qualify a reference/rater. No actual fixture has
been executed here. All first executions require preservation and independent
source review/root release, with first failures retained before repair.

Syntax compilation completed with exit0 for both files. This is source parsing,
not a reporter/model/data/test execution or empirical qualification. Dependencies
are the frozen protocol/reference/instruction files plus the exporter's inert
stdlib public functions. Root will bind all exact source hashes before execution.

CLI preparation writes --requests-output as a separate exclusive JSON list for
the API runner, --lineage-output as exclusive stage lineage, and --output as
preparation metadata. Collect additionally requires --stage-manifest and its SHA,
--lineage and its SHA, bound requests/completion, and reviewed --response-root.
All raw dependency paths should be repository-relative to match the runtime
runner. A report/audit/rate stage lineage is created before that stage, bound
in its reviewed manifest, and retained in collection and summary.
