# First operational resource review

**A tool-assisted, record-by-record worker procedure is feasible in principle under the frozen 24-position chunk contract. Completion within the host is not demonstrated.** A roughly 2MB chunk need not be inserted into a single prompt or emitted in a final chat message. No known host context/output/time ceiling was supplied or established; the byte measurements alone justify neither a failure declaration nor a promise of success. Exact bindings and exposure are in [metadata.json](metadata.json).

The protocol fixes 23 chunks per stream, 24 positions per chunk and two streams: 46 fresh contexts and 1,104 retained review positions. The preparer stores each record's full text, canonical annotation, 12 components, every evidence/binding path and property table. The closed output schema requires the complete 24-record grade. The collector accepts disk artifacts, retains exact first bytes and invalidates an entire chunk on any record failure; it does not require the grade to be transmitted as one conversational response. These are operational affordances, not semantic qualifications.

## Concrete procedure to freeze before launch

1. **Keep the original terminal gate.** Do not prepare or expose actual reference packets while the original process remains live. Root must first observe its actual terminal state, preserve the correct completion/interruption evidence, run the already-reviewed actual preparation/lineage checks and bind the exact complete manifest/chunks. No new scientific call or trial review is needed to make this decision.
2. **Reserve the complete workload once.** Fix both streams, all 23 chunks in the frozen order, 46 distinct fresh context IDs, each exclusive first-artifact path, exact instructions/schema/reference/chunk hashes and root observation/retention rules. Limit simultaneous workers to available host capacity, but do not split a 24-position chunk across replacement contexts, omit a hard chunk or change the review unit. Each chunk gets its originally assigned fresh context; no peer grades or expected grammar verdict enter it.
3. **Use local source views instead of one huge prompt.** The assigned worker receives the frozen reference/protocol/schema and its bound chunk path. A read-only JSON view can select one exact record by original ID and paginate its text/annotation, component inventory, evidence entries, binding candidates and construction units. Every page must identify its record/path and full inventory counts; no tool-output truncation may masquerade as complete inspection. All property-table entries remain accessible. Inspect whole report meaning, each original evidence-list position and every binding; query exact units/relative values as needed. Geometry can locate a candidate operand, never choose its semantic meaning. Repeated evidence at distinct paths remains distinct work.
4. **Persist first judgments in the same context.** The worker can write immutable first working fragments by record or evidence-path block using exclusive creation. A mechanical helper may copy fixed IDs, original statuses, paths, schema envelopes and exact referenced values from the source; the reviewer must supply assessments, semantic roles, operands, reasons and compatibility judgments. Helpers must not default semantic fields to supported/absent, infer A-source truth, fill unreviewed slots or select favorable evidence. Keep a path/count ledger and hashes so the context need not repeatedly carry previous records' full bytes. No fresh agent takes over unfinished semantic work.
5. **Assemble the one complete first artifact mechanically.** Once all 24 first records exist, concatenate them in the fixed order and add the bound chunk envelope, preserving every judgment/value. Write the reserved final chunk file exclusively; return only its path/hash in the worker's short final message. If a helper is introduced, bind its exact instructions/source and check its copying/assembly on fictional inputs before actual launch. This is formatting machinery, not another qualification trial. Do not provide collector/schema failure feedback for rewriting an already saved first judgment or rerunning a worker.
6. **Retain operational failure as failure.** If the context terminates before completion, preserve its actual working fragments/tool observations and any reserved first file exactly as they stand. Do not manufacture 24 placeholder judgments, replace a missing fragment, salvage good rows or recommission the chunk. Root records the actual terminal observation. The collector then retains the whole 24 positions as unestablished. Unsaved nonterminal output remains pending rather than terminal by timeout. A completed final file is collected once under the existing hash/receipt contract; an invalid file is not repaired.

Intermediate working fragments are an operational proposal, not an amendment granting independently usable grades. Freeze their first-write/assembly policy before launch. They do not change the frozen final schema, 46-context allocation or whole-chunk invalidation. Any partials remain preserved evidence if final assembly fails; they cannot become a row-salvage route.

## Real remaining constraints

The reported still-live original process blocks actual preparation/launch now. After terminal verification, the concrete pre-launch work is a complete assignment/receipt manifest and explicit worker source-view, first-write and assembly instructions. If reusable mechanical helpers are used, their exact copying contracts need source/fictional verification before actual judgments. A hidden source/view filter or semantic auto-fill would be a real protocol violation; the existence of a large packet is not one.

Unknown aggregate context, output, duration and tool-call budgets remain a genuine availability risk. Paginated file reads and disk writes reduce pressure from full-chunk prompt/final-response size; they cannot remove the cost of reading and judging the evidence. No fresh-context restart, automatic continuation in another context, shortened inventory or smaller final chunk is licensed if a host limit is reached. Resource failure could therefore leave all 24 positions unestablished, as already required. The presence of filesystem/tool access makes this a plausible operational route; it is not a measured success probability or a claim that every chunk can finish.

Do not use repeated boilerplate verdicts as a compression substitute for specific reasoning. Nonestablished source annotations require their original diagnostics and empty semantic inventories, not fabricated review work. Established records still require all 12 component judgments, all evidence positions, every binding and explicit property reasons where cited. Compact serialization, copied identifiers and exact-value lookup can reduce avoidable transcription, but cannot replace those judgments.

The 552 narrator-availability entries and 684 causal pairs remain retained by preparation/collection; they are not additional narrator-review tasks or sham-report opportunities for these workers. This procedure cannot qualify V5, release narrator fidelity, prove semantics from source geometry, or supply new independent-system evidence. It supports preserving the existing template-control analysis while exposing its operational failure rate honestly.
