# Learned attention-content v1: evaluator collector software

The collector implements the approved amended design's fixed command schedule,
balanced per-address symbol mappings, same-V actual executor, fifteen-transition
common history, three prospective alternatives at each decision and reachable
donor prefixes. Source inference must never receive this evaluator bundle.

The first five fixtures use handcrafted two-world maps and manually specified
commands/mappings. They check exact recovery from V after a lossy command,
matching-command fork identity, nonselected copies, donor prefix/reveal indices,
three-operator family coordinates and rejection of a sealed split before rendering.
No registered world schedule or renderer, frozen artifact, trained source,
optimizer or Reporter is executed. Both source files were syntax-compiled before
that exclusive first execution; its unchanged log and source hashes are retained.

The first fixture run passes 5/5 checks. These are software results, not evidence
that a production phase was sealed or a learned state represents any content.
`collect_worlds` requires an upstream runner-verified release; its split argument
is a local guard rather than immutable receipt verification. The future phase
runner and independent reconstruction must bind inputs, verify native acceptance,
enforce release receipts and construct permitted model observations.

Independent static collector review is separate and must remain explicit about
these limits. The source closure, runner and verifier require full pre-execution
review and committed registration before any actual A fit or heldout release.
