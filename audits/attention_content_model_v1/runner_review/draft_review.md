**R1 — native acceptance must match the successfully reconstructed bytes.**
Transport identity and passing summary alone do not bind current results,
completion and archives to the passing review. Freshly hashing those files can
accept changed bytes alongside an unchanged old passing review. Compare current
digests with the passing `checks` entries named `actual_results_bytes/<path>`,

result/archive hashes and bind accepted review/verifier preservation provenance.
Do not assume a nonexistent top-level review result hash. Native gates stay fixed.

**R2 — require complete phase artifact inventories and linked receipts.**
`receipt` accepts an empty/partial artifact-hash map, although later phases load
fixed fit archive paths. Require those per-seed archives/log and required fit
component/manifests to be covered. Heldout must compare the dev receipt's written
`fit_receipt_sha256` to the accepted fit receipt; it currently never reads that
link. Require registration→fit→dev ancestry and record accepted commit/receipt/
assessment hashes in claims/completions. Assessment fitted-hash assertions must
agree with actual dev receipt/bundles and independently reconstructed usage.

**R3 — gate fit completion and visibility.**
The runner serializes unchecked `fit_sources` returns and can write a completed
fit receipt without validating declared checkpoints, normalizer, optimizer terminal
states, training log or `fit_visibility`. Require exact source/key inventories,
300 updates per source, initialization seeds/parameter counts, fit-only coordinates,
finite retained outputs and evidence of no dev/heldout forward calls. Bind fitted
artifacts/training/permission manifests before dev release. Internal engine
assertions need a fixed returned schema and runner enforcement.

**R4 — require named hard invariants and source-call manifests.**
The boolean checker rejects false/nonboolean leaves but accepts `{'ok': True}`.
Freeze required named invariants and per-opportunity counts/shapes for observation,
source isolation, restoration, alias/comparator and ledgers. Require scoped dev
assessment and independent reconstruction, preserving limited/negative semantic
status without adding a performance/manner threshold for technical heldout release.
The evaluator episode contains all W, mappings, truth and future targets; trusting
its engine is not itself a leak, but timestamp labels/booleans cannot prove correct
source arguments. Retain actual observation/feedback tensors or hashes and compare
with independent permitted histories. W15 is archived/revealed only: no scored
t=15 prediction or extra terminal update. Future engine/verifier review must
establish this; the runner alone does not.

**R5 — finish source/verifier/permission closure before registration.**
Required sources do not include an independent reconstruction verifier or explicit
permission schema. Final engine transitive imports are not yet reviewed. Bind that
complete closure, verifier, shapes/dtypes, seeds, controls and source-indexed
ledgers. A `complete_preexecution_review` receipt cannot be issued for this draft.
Keep immutable input registration distinct from fitted/dev phase additions.

**R6 — retain the original exception despite retention errors.**
The handler saves a tensor archive before writing `failure.json`. Torch import or
serialization failure in that handler can mask the original traceback and prevent
any failure receipt. Capture traceback first, write a stdlib-only failure receipt,
then attempt partial tensor retention and record secondary failures separately.
Bind registration, phase/seed, log and available artifacts. During interrupted
`fit_sources`, runner partial state currently contains only the episode; add a
bounded progress/snapshot callback or explicitly retained engine progress payload.
Previous completed seeds are preserved, but an interrupted seed remains incomplete.
No automatic retry or favorable fallback is permitted.
