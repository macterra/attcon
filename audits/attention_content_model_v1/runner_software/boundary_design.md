2026-10-11. This revision addresses the first R1–R6 draft review without
releasing task data. The original draft source, review and help output remain
preserved at their original commits. This record precedes fixture execution.

The runner pins the accepted native corrected review manifest and compressed
result to published commit `c84d3dabc0e3ca8b2d9898b8554b032556c0acff`, checks
current accepted archive/result/completion hashes, requires an exact complete
reviewed registration, and links phase receipts through commit ancestry. Returned
fit checkpoints, fit-only coordinates, source seeds, optimizer settings/steps and
ordered logs are validated. Returned evaluation gates must have the engine's
exact named Boolean inventories and opportunity shapes, including assembly,
delayed visibility, actual update-call counts and actual-state compaction. These
checks are not independent reconstruction or proof of an optimizer trajectory.

First execution failures preserve the original traceback using stdlib JSON before
attempting tensor retention, retain the active seed and already returned fitted
outputs, and record secondary retention failure separately. The exclusive claim
prevents automatic reruns.

Seven prospective fixtures use temporary files and mocked phase bindings only:
empty artifact inventory rejection, foreign registration rejection, complete
receipt binding, changed committed source rejection, accepted-native publication
pinning, omitted source closure rejection, and original import failure plus
secondary retention failure with retry rejection. The final fixture deliberately
rejects the torch import; no torch, engine, tensors, native archives, model weights,
worlds, fitting, development, heldout data or Reporter calls are used. Mocked
bindings test control flow, not actual GitHub publication or scientific inputs.

Exact source hashes are in `boundary_preexecution_metadata.json`. Independent
static review must approve these exact bytes before the one first fixture run;
that source/review milestone is committed and pushed before execution. Preserve
the first log and exit status without overwriting or silently repairing failures.

Complete production approval remains absent. The independent verifier is still
being integrated against E1–E5 engine corrections. A subsequent heldout boundary
must additionally bind a genuinely passing independent dev reconstruction report
and a fixed-dev semantic disposition; a caller's unbound success assertion alone
is insufficient. No production phase or reporting release follows from these
bounded software fixtures, and the qualia-source goal remains unachieved.
